## 1. 项目概述

开发一款**局域网（内网）测速软件**，用于测量手机与电脑之间通过本地网络（WiFi / 有线）通信时的真实速度，帮助用户排查网络问题、验证 WiFi 信号质量、检验网线/交换机等设备的实际带宽。

- **电脑端**：以**终端（命令行）程序**形式运行，作为测速服务端。
- **手机端**：**Android App**，作为测速客户端，连接电脑进行测速。

整个测速过程**完全在局域网内完成，不依赖互联网**。

## 2. 目标与使用场景

### 2.1 主要场景

| 场景 | 说明 |
| --- | --- |
| 排查家庭/办公室网络问题 | 手机连接 WiFi 测速，判断 WiFi 链路是否达标、是否存在干扰 |
| 验证 WiFi 信号质量 | 结合 Ping / 抖动 / 丢包率判断无线链路稳定性 |
| 验证有线设备性能 | 电脑接网线作为基准，对比手机无线测速结果 |
| 检验路由器 / 交换机 / 网线 | 通过测速数值判断链路瓶颈所在 |

### 2.2 非目标（本期不做）

- 不测**互联网带宽**（外网速度，如 speedtest.cn 等）。
- 不要求手机端支持 iOS。
- 不要求电脑端支持 macOS / Linux。
- 不做多设备同时测速的协调（电脑同一时刻只服务一台手机的完整测速流程）。

## 3. 系统架构

```
┌───────────────────────────┐       局域网        ┌───────────────────────────┐
│  电脑端（Windows 终端）     │ ◄────────────────► │  手机端（Android App）      │
│  Python 测速服务端          │  TCP 控制/数据通道   │  Flutter 测速客户端        │
│  - 监听端口，等待手机连接    │                    │  - 自动发现/手动输入 IP    │
│  - 接收测速指令并回传数据    │  UDP 广播/组播       │  - 发起测速、绘制曲线      │
│  - 打印连接与测速日志        │ ◄────────────────► │  - 保存历史记录           │
└───────────────────────────┘   自动发现广播        └───────────────────────────┘
```

### 3.1 角色划分

| 角色 | 端 | 职责 |
| --- | --- | --- |
| 测速服务端（Server） | 电脑端 Python 程序 | 监听端口；响应手机的测速请求；下载测速时持续下发数据；上传测速时接收数据；统计并返回结果 |
| 测速客户端（Client） | 手机端 Flutter App | 发现/连接服务端；发起测速；统计下载、上传、延迟、抖动、丢包率；展示曲线并保存历史 |

### 3.2 通信设计（草案）

| 通道 | 协议 | 用途 |
| --- | --- | --- |
| 自动发现 | UDP 组播/广播（或 mDNS） | 手机端自动发现局域网内的电脑服务端，免手动输入 IP |
| 控制通道 | TCP + 换行分隔 JSON | 握手、下发测速参数、上报进度、返回结果 |
| 数据通道 | 原始 TCP 流 | 上传/下载测速的实际数据搬运，固定大小数据块填充，保证测速准确性 |

> 详细协议字段在开发阶段以《协议设计文档》形式补充，本节仅确定方向。

## 4. 功能需求

### 4.1 电脑端（Python 服务端）

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| S1 | 启动与参数 | 终端命令启动，支持参数：监听端口（默认如 8899）、绑定地址、最大并发客户端数 | 必选 |
| S2 | 本机信息展示 | 启动后打印本机所有局域网 IP 与端口，方便用户手动在手机输入 | 必选 |
| S3 | 自动发现广播 | 周期性广播自身信息（名称、IP、端口、版本），供手机自动发现 | 必选 |
| S4 | 握手与鉴权 | 客户端连接时完成握手；若配置了访问口令则校验口令（默认不开启） | 可选 |
| S5 | 下载测速 | 按客户端参数持续向客户端发送数据，统计吞吐量 | 必选 |
| S6 | 上传测速 | 接收客户端数据并统计吞吐量 | 必选 |
| S7 | 延迟/抖动/丢包测试 | 响应客户端的小包 Ping 测试；统计丢包 | 必选 |
| S8 | 日志输出 | 终端打印：连接事件、测速过程、每次测速结果摘要（速率、时长、客户端 IP） | 必选 |
| S9 | 优雅退出 | Ctrl+C 退出并清理资源 | 必选 |

### 4.2 手机端（Flutter Android App）

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| A1 | 服务端发现 | 自动扫描局域网，列出发现的电脑服务端（名称 + IP）；支持点击连接 | 必选 |
| A2 | 手动连接 | 手动输入 IP 与端口连接服务端（自动发现失败时的兜底方案） | 必选 |
| A3 | 测速参数设置 | 可调参数：测速时长（如 5/10/30/60 秒）、并发连接数（如 1/2/4/8）、是否测试上传、是否测试 Ping | 必选 |
| A4 | 一键测速 | 按顺序执行：Ping/抖动/丢包 → 下载测速 → 上传测速，全程显示进度 | 必选 |
| A5 | 实时速度曲线图 | 测速过程中每秒刷新一次速度曲线（下载、上传） | 必选 |
| A6 | 结果展示 | 展示：下载速度、上传速度、平均/最小/最大延迟、抖动、丢包率（单位 Mbps / ms / %） | 必选 |
| A7 | 历史测速记录 | 本地保存每次测速结果（时间、服务端、参数、各项指标）；列表页可查看详情、删除 | 必选 |
| A8 | 设置页 | 默认测速参数、服务端名称等持久化设置 | 可选 |
| A9 | 中文界面 | 全部界面使用中文 | 必选 |

### 4.3 测速指标定义

| 指标 | 单位 | 定义与算法 |
| --- | --- | --- |
| 下载速度 | Mbps | 手机从电脑接收数据的平均吞吐量 = 总字节 × 8 / 耗时 |
| 上传速度 | Mbps | 手机向电脑发送数据的平均吞吐量 |
| 延迟（Ping） | ms | 小数据包（如 64B）往返时间，统计最小值 / 平均值 / 最大值 |
| 抖动（Jitter） | ms | 相邻 Ping 值之差的平均绝对值，反映稳定性 |
| 丢包率 | % | 发送的数据包中未收到回应的比例 |

### 4.4 数据存储（手机端）

| 数据 | 存储方案 | 说明 |
| --- | --- | --- |
| 历史测速记录 | SQLite（sqflite） | 字段：id、时间戳、服务端 IP/名称、测速参数、各项指标 |
| 用户设置 | SharedPreferences | 默认测速参数、最近连接的 IP 等 |

## 5. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 运行环境 - 电脑端 | Windows 10/11；Python 3.10+；仅依赖标准库或少量轻量库，安装简单 |
| 运行环境 - 手机端 | Android 8.0（API 26）及以上；无需 root |
| 测速能力 | 支持千兆有线（≥ 900 Mbps 实测）与 WiFi 6 手机测速；高带宽下不因 Python 单线程成为瓶颈（上传测速使用多线程/异步） |
| 采样精度 | 速度曲线每秒至少 1 个采样点；速率显示保留 2 位小数 |
| 准确性 | 与 iperf3 在同条件下测得的吞吐量偏差 ≤ 10% |
| 自动发现 | 手机进入测速页后 10 秒内完成一次发现扫描 |
| 稳定性 | 测速中断（手机息屏、断连）时服务端不崩溃，可继续接受新连接 |
| 安全性 | 服务端仅监听局域网；不向公网开放；可选访问口令防误连 |
| 界面语言 | 中文 |
| 日志语言 | 中文 |

## 6. 技术选型

| 端 | 技术 | 选型理由 |
| --- | --- | --- |
| 电脑端 | Python 3.10+（asyncio / socket） | 终端运行、脚本简单易改、跨版本兼容性好 |
| 手机端 | Flutter（Dart） | 一套代码可扩展 iOS；UI 绘制流畅，曲线图组件成熟（fl_chart 等） |
| 手机端存储 | sqflite + shared_preferences | 本地轻量存储 |
| 自动发现 | UDP 组播广播（服务端 Python 端实现 + 手机端监听） | 零依赖、实现简单；若体验不佳可换 mDNS/zeroconf |
| 曲线图 | fl_chart（或自绘 CustomPaint） | 实时速度曲线 |

## 8. 开发里程碑

| 阶段 | 内容 | 验收点 |
| --- | --- | --- |
| M1 服务端原型 | Python 服务端：下载/上传测速、日志、参数 | 终端可启动，能用 iperf3 风格工具或脚本验证吞吐 |
| M2 手机端最小可用 | App 手动输入 IP → 下载/上传测速 → 结果展示 | 手机与电脑实测出速度，数值合理 |
| M3 完整指标 | 延迟/抖动/丢包测试 + 并发参数 | 各项指标正常输出 |
| M4 体验完善 | 自动发现、实时曲线图、历史记录、设置页 | 全功能可用 |
| M5 打磨验收 | 精度校准（对照 iperf3）、稳定性、界面打磨、打包 APK | 满足第 5 节全部非功能要求 |

## 9. 验收标准（汇总）

1. 电脑端执行一条命令即可启动服务端，并打印本机 IP、端口。
2. 手机 App 能通过**自动发现**或**手动输入 IP** 两种方式连接服务端。
3. 一次测速可完成：延迟/抖动/丢包 → 下载 → 上传，并展示全部指标。
4. 测速过程实时显示速度曲线，每秒至少一个采样点。
5. 测速结果自动保存为历史记录，App 重启后仍可查看。
6. 千兆有线环境下实测吞吐 ≥ 900 Mbps；与 iperf3 偏差 ≤ 10%。
7. 测速时长、并发数可配置并生效。
