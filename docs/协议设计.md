# 内网测速 · 通信协议设计 v1

> 本文件是电脑端服务端（Python）与手机端客户端（Flutter）之间的**唯一契约**，两端实现必须严格遵循。
> 需求文档：`docs/需求文档.md`

---

## 1. 端口与常量

| 常量 | 值 | 说明 |
| --- | --- | --- |
| TCP 服务端口 | 8899（`--port` 可改） | 控制连接 + 测速数据连接共用 |
| UDP 发现端口 | TCP 端口 + 1（默认 8900，`--discovery-port` 可改） | 自动发现广播/探测 |
| 广播目标 | `255.255.255.255:UDP端口` | 仅同一广播域内有效 |
| 广播间隔 | 3 秒 | 服务端周期发送 announce |
| 消息编码 | UTF-8，单行 JSON，以 `\n` 结尾 | 控制连接与数据连接头部 |
| 数据块大小 | 65536 字节（64 KiB） | 可配置 `--block-size` |
| 协议版本 | 1 | `version` 字段 |

**Socket 选项**：控制连接与数据连接均开启 `TCP_NODELAY`；数据连接尽量调大收发缓冲区（≥ 1 MiB）。

## 2. 自动发现（UDP）

### 2.1 服务端行为
1. 绑定 `0.0.0.0:UDP端口`。
2. 每 3 秒向 `255.255.255.255:UDP端口` 广播一次 announce 报文。
3. 收到 probe 报文后，向**发送方地址**单播回复 announce 报文。

### 2.2 报文格式

announce（服务端 → 客户端）：
```json
{"type":"lan-speedtest-announce","name":"DESKTOP-ABC123","ip":"192.168.1.5","port":8899,"version":1}
```

probe（客户端 → 广播地址）：
```json
{"type":"lan-speedtest-probe","version":1}
```

### 2.3 客户端行为
1. 进入发现页时绑定 UDP 端口并发送一次 probe。
2. 持续监听 announce 报文；同一 IP+端口 的报文**去重刷新**（更新为最新）。
3. 显示：名称、IP、端口。

## 3. 控制连接（TCP）

### 3.1 握手

客户端 → 服务端：
```json
{"type":"hello","app":"lan-speedtest","version":1,"name":"手机设备名"}
```

服务端 → 客户端（无口令时）：
```json
{"type":"welcome","name":"DESKTOP-ABC123","version":1,"tcpPort":8899,"maxConcurrency":8}
```

服务端需要口令时回复：
```json
{"type":"auth-required"}
```

### 3.2 认证（可选）

客户端 → 服务端：
```json
{"type":"auth","password":"1234"}
```

服务端回复：`welcome`（成功）或 `{"type":"auth-failed"}`（失败后关闭连接）。

### 3.3 Ping 测试（延迟/抖动/丢包）

客户端 → 服务端，逐条发送（默认 20 条，间隔 30ms，`--ping-count` 可调）：
```json
{"type":"ping","seq":0,"ts":1717000000000}
```
- `seq`：从 0 递增的序号
- `ts`：客户端发送时的毫秒时间戳

服务端 → 客户端，**原样回显**：
```json
{"type":"pong","seq":0,"ts":1717000000000}
```

客户端统计：
- **RTT** = 收到 pong 的时刻 − `ts`
- **平均/最小/最大延迟** = RTT 的均值/最小/最大
- **抖动** = Σ|RTTᵢ − RTTᵢ₋₁| / (n−1)
- **丢包率** = (发送条数 − 收到条数) / 发送条数 × 100%

### 3.4 测速会话

客户端 → 服务端：
```json
{"type":"start","test":"download","duration":10,"concurrency":4,"blockSize":65536,"token":"a1b2c3d4"}
```
- `test`：`"download"` 或 `"upload"`
- `token`：客户端生成的随机字符串，标识本次会话（数据连接携带）

服务端 → 客户端：
```json
{"type":"started","test":"download","duration":10,"concurrency":4}
```

### 3.5 测速完成上报

客户端 → 服务端：
```json
{"type":"complete","test":"download","token":"a1b2c3d4","bytes":123456789,"durationMs":10000,"speedMbps":98.76}
```

服务端 → 客户端：
```json
{"type":"complete-ack"}
```

### 3.6 结束

客户端发送 `{"type":"bye"}` 后主动关闭控制连接（bye 可选，直接关闭亦可）。

## 4. 数据连接（TCP）

> 每次测速，客户端建立 `concurrency` 条并行数据连接，连接同一 TCP 端口。
> 每条数据连接**独立计数**，客户端汇总后计算总吞吐。

### 4.1 连接头部（客户端 → 服务端，首行）

```json
{"type":"data","test":"download","token":"a1b2c3d4"}
```

### 4.2 下载测速（download）

1. 客户端在控制连接发 `start(test=download)`，收到 `started` 后建立 N 条数据连接。
2. 每条数据连接发送头部后，**服务端持续发送原始字节**（每块 blockSize），直到连接被关闭。
3. 客户端按 blockSize 读取并计数，持续 `duration` 秒后关闭全部数据连接。
4. 服务端在 `sendall` 异常（连接关闭）时结束该连接，记录已发送字节。

### 4.3 上传测速（upload）

1. 客户端在控制连接发 `start(test=upload)`，收到 `started` 后建立 N 条数据连接。
2. 每条数据连接发送头部后，**客户端持续发送原始字节**，持续 `duration` 秒后关闭（`shutdown(SHUT_WR)` 或直接 close）。
3. 服务端循环 `recv` 计数直到 EOF（recv 返回空），记录已接收字节。

### 4.4 速率计算（客户端）

- **速度 Mbps** = 总字节 × 8 / 实际耗时（从首字节收发开始计时）
- **采样**：每秒 1 个采样点（各连接字节数之和 / 1s × 8），用于实时曲线

### 4.5 服务端日志

连接建立/关闭、每会话实际传输字节、客户端上报结果，均输出中文日志。

## 5. 错误处理

| 场景 | 服务端行为 |
| --- | --- |
| 无法解析的 JSON 行 | 回复 `{"type":"error","code":"bad-message"}`，继续 |
| 未知 `type` | 回复 `{"type":"error","code":"unknown-type"}` |
| 数据连接头部非法 | 直接关闭该数据连接 |
| `test` 字段非法 | 回复 `{"type":"error","code":"bad-test"}` |
| 并发超过 `maxConcurrency` | 回复 `{"type":"error","code":"too-many-clients"}`（新控制连接拒绝） |
| 认证失败 | `{"type":"auth-failed"}` 后关闭连接 |

客户端对 `error` 报文应显示可读的中文错误提示并中止当前操作。

## 6. 兼容性约束

- 两端 `version` 不一致时：客户端检测到后提示「服务端版本不兼容」。
- 所有 JSON 必须为单行（无内嵌换行）。
- 整数/浮点字段不做精度要求，但速率显示保留 2 位小数。
